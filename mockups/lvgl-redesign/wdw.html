Wet / dry / wet routing

Static layout mockups — no production UI wiring. The proposed topology has two complete lanes: a centred dry amp/cab path and a stereo wet amp/cab path with time-based effects. Direct input is never shown as an output choice. The device view is a glanceable performance surface; the manager view is where lane editing, mix placement and measured admission details live.

Manager rule: this is the detailed authoring surface. It exposes the same vocabulary as the device (lane, block, cab, dry/wet contribution) and adds only information that is useful off stage: insertion points, measured latency, worker placement, ring depth and rejection conditions.

These are visual contracts for the next implementation pass. They intentionally do not define preset schema, gestures or manager API details; those remain implementation/design work after this feasibility gate.
