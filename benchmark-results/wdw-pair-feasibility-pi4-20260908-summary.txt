Two-lane wet/dry/wet pair-executor validation
Date: 2026-09-08
Target: Raspberry Pi at 192.168.88.12 (aarch64, service stopped during probe)

This run uses the new pair-aware executor.  The dry and wet workers share one
generation ring, so publication can only copy a complete dry/wet pair from the
same input generation.  It replaces the earlier independent-executor probe,
which could report a generation mismatch when one lane completed first.

Measured topology
  Dry lane: Rat -> NAM (JCM800) -> dense synthetic 8192-frame cab IR
  Wet lane: NAM (Ampeg/Dumble) -> dense synthetic 8192-frame cab IR
             -> stereo digital delay -> stereo room reverb
  Audio callback: CPU 2, SCHED_FIFO priority 60
  Dry worker: CPU 0, wet worker: CPU 3, SCHED_FIFO priority 69
  Pipeline: two bounded slots, paced 48 kHz, 64-frame blocks
  Publication: pair-complete only; one startup silence block; no raw-input bypass

Run: 200 warmup blocks plus 5,000 timed blocks

  pair underflows               1
  pair submission misses        0
  initial silence blocks        1
  callback mean / p99 / p999    10.433 / 16.796 / 19.722 us
  callback maximum              20.574 us
  callback deadline misses      0 / 5,000
  dry worker calls, mean / max  5,200; 961.986 / 1,275.241 us

  non-finite/fault blocks       0 / 0 / 0

The single underflow is the expected startup condition; the first output is
silence and no stale or raw signal is emitted.  After startup every published
output is a generation-matched pair, and the bounded ring recorded no missed
submissions.  The Pi's ardor-pedal telemetry remained healthy after restart:
over=0, gaps=0, bypassed=0, worker_over=0, nonfinite=0, block_mismatch=0.

Stress follow-up
  A 20,000-block / 64-frame run still had zero submission misses and zero
  deadline misses, but recorded 14 bounded pair underflows (one startup plus
  occasional one-block holds) while the Rat-enabled dry worker reached
  1,623.648 us; maximum observed pair age was one block.  This confirms that
  64 frames is usable only with the explicit hold/silence policy; it is not the
  safest zero-underflow admission point.
  A 20,000-block / 128-frame run had one startup underflow, zero submission
  misses, zero deadline misses, and no non-finite blocks.  Its worker maxima
  were 2,355.834 us dry and 1,814.982 us wet against a 2,666.667-us quantum;
  callback mean / p99 / max were 23.498 / 51.593 / 692.315 us, and maximum
  pair age was zero after the startup block.
  The 128-frame result is therefore the preferred default for this exact
  topology; 64 remains an opt-in mode subject to runtime underflow telemetry.

Measured-latency rerun
  The harness now probes each prepared lane with a control-thread impulse,
  resets both chains, and passes the measured first-arrival values into the
  program's fixed alignment buffers.  The exact 20,000-block / 128-frame Pi
  run measured dry latency 0 frames and wet latency 31 frames, then produced
  20,497 matched pairs, three bounded one-block underflows, zero submission
  misses, zero callback deadline misses, and zero non-finite blocks.  Worker
  maxima were 2,353.426 us dry and 1,900.056 us wet; callback mean / p99 /
  max were 32.170 / 610.908 / 756.018 us.  The result is in
  `benchmark-results/wdw-program-feasibility-pi4-20260908-128-20k-calibrated.csv`.

Three-slot admission follow-up
  Repeating the calibrated run with a three-slot pair ring reduced the result
  to the expected single startup underflow, with zero later pair age,
  submission misses, callback deadline misses, and non-finite blocks.  Worker
  maxima were 2,339.389 us dry and 1,829.333 us wet; callback mean / p99 /
  max were 33.417 / 608.500 / 736.611 us.  The additional slot is a small
  bounded-memory cost and is the preferred Pi admission default; two slots
  remain useful for memory-constrained experiments.  CSV:
  `benchmark-results/wdw-program-feasibility-pi4-20260908-128-20k-calibrated-slots3.csv`.
